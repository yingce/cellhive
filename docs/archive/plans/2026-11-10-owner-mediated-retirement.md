# Implementable owner-mediated retirement plan

Implementation plan, 2026-11-10. Authorized under the existing idle-latency optimization goal; implementation and acceptance pending. Repository: /opt/cellhive-worktrees/celld-ltx-migration. This plan originated as a read-only design review; implementation status is tracked below. This is feasible without new remote objects, but is a protocol change across control, owner, admission and replica; not a cache-only patch.

## Critical source findings beyond the prior review

* The only production `BlockResource` callers are `Server.revokeResource` and `ResourceCleanupPass` in internal/server/resource_cleanup.go. Both must disappear before local no-expiry generation reuse is enabled.
* Retry-after-commit already partly works: control.Store.DeleteResource (store.go:2526) sees an absent resource with an existing cleanup row and returns nil from its transaction, then invokes OnResourceRevoked again. resource_admin.go:218 also explicitly finds that cleanup row. Preserve this job ID, do not create a new deletion identity on retry.
* A separate durability problem must be fixed: DeleteResource calls OnResourceRevoked AFTER its SQLite transaction but INSIDE the caller's capturedWrite callback. capturedWrite (server.go:3413) returns immediately on callback error, without Capture.Wait. A failed remote retirement must not be treated as proof of a durable pending cleanup. Separate intent commit + Capture.Wait from remote barrier. Also avoid remote callback while Store.resourceMu is held: the remote validation callback must not reenter a held control transaction/resource lock.
* Existing cleanup RPC serializes ResourceCleanup directly, but LeaseToken/LeaseUntilMs are json:"-" (control/cleanup.go). The receiver currently does not ValidateResourceCleanupLease at all. A new internal envelope must explicitly include the token, expiry, expected owner tuple, and job identity; validation must route to the current control owner, not read a stale local control replica.
* Store.forget (cellstore.go:640) deliberately does NOT close evicting before draining busy requests: already admitted requests can still call Cell, and Cell waits on evicting. Reusing evicting as an early retirement barrier deadlocks. Add a separate admission-only retiring state.
* ClaimWithReset rejects cur.Retired before takeover. Existing cleanupResourceData's ordinary Claim cannot recover a dead owner after BlockResource. A scoped administrative claim is required.
* Lease health is necessary but insufficient: LocalReadGuard currently protects owner revision/releasing/lease evidence, not resource retirement. It becomes usable only after every retirement publication observes the new barrier protocol.

## Stage 1: contract, intent durability and API result

Update docs/decisions.md and docs/known-issues.md first, then relevant deletion/ownership docs. Keep deletion success meaning logical revocation/fence durable, physical purge asynchronous. Under an unreachable live owner, delete returns retryable failure/pending within the existing deadline; it cannot promise successful immediate revocation. This availability change is necessary: zero periodic remote checks and unilateral remote successful revocation cannot both hold during a partition.

Refactor control.Store.DeleteResource into durable intent mutation plus server orchestration. Suggested `DeleteResourceIntent` returns the existing/new cleanup identity; leave non-KV/queue handling unchanged. Server helper performs `capturedWrite(control.ScopeFor(ns), intent)` to completion, THEN routes retirement. Migrate every relevant caller; avoid retaining a callback invoked before durability proof. Existing pending cleanup row remains sole remote intent, with existing tombstone/retirement tables and own.json fields. No new COS object or polling registry.

Use existing ClaimResourceCleanup/ContinueResourceCleanup/FinishResourceCleanup state machine to obtain a short, captured cleanup lease for synchronous preparation. If another cleaner already holds it, join/retry or report pending; never steal a valid lease. Preparation success need not mean purge complete: return job to pending via existing continuation semantics, or let the active cleaner finish. API failure body should include cleanup identity/status (without internal lease token); map both initial and repeated failure consistently to 503/resource_revocation_failed. Existing code currently returns initial 500 and retry 503. Repeated DELETE must rerun barrier for the same job; completed job succeeds. Re-fetch response job after orchestration instead of returning the pre-call snapshot. If intent Capture.Wait itself fails, do not begin destructive preparation or claim durable intent.

## Stage 2: admission barrier independent of eviction

Add cellstore scope-lifecycle state under Store.mu: generation, owner incarnation/revision, retiring job, active request count (reuse busy), and explicit activation validity. Proposed `BeginResourceRetirement(ctx, scope, job, expectedIncarnation)` atomically marks retiring and invalidates local generation fast guards, then waits for busy/opening work to drain. Cancellation leaves retiring set; a same-job retry resumes. A different/stale job fails. New BeginRequestContext calls for this scope return ErrResourceDeleted while retiring. Existing admitted code can still call Cell, capture, and finish; do NOT set evicting until busy has drained.

Add an explicit guarded activation/reopen operation, allowed only after authoritative fresh owner+resource snapshot and generation transition. Never clear retiring merely on an absent fence: a timeout may have installed the barrier before publication. Same-generation abort recovery must first invalidate/release local authority and re-resolve under coordinator authorization; simplest initial implementation remains closed until job retry succeeds. Normal Forget/eviction must not erase retiring or generation admission evidence. Pin must not bypass retirement: current ForgetWithVerify returns nil for pinned scopes.

Bound lifecycle memory by tying entries to retained local ownership/open cells/active operations. Do not LRU-evict a blocked live owner's state. To reclaim, first discard all local authority and generation guards and release/lose ownership, then force a fresh activation before serving; after durable retirement own.json itself rejects admission. Pending closed live entries are bounded by retained owned scopes, and require observable count/age; a blanket forever map is not acceptable. Existing on-disk .resource-generation marker remains generation evidence, not an admission authorization.

## Stage 3: owner-bound conditional retirement publication

Introduce internal prepare-retirement RPC separate from cleanup-data, authenticated by existing internal transport. Envelope: ns/kind/name/dataScope/jobID, cleanup lease token/deadline, expected {Node,Session,Epoch}, and expected source incarnation. Do not route it through ordinary forwardOrClaim/BeginResourceRequest: it must be able to act on blocked resources and must not count itself in drain.

Receiver validates current cleanup identity/lease with current authoritative control owner, exact scope mapping and owner tuple, marks admission closed, drains admitted operations and capture dependencies, then publishes retired=true/jobID/retiredEpoch >= drained epoch in ONE conditional own.json update. New replica API e.g. `RetireOwnedResource(ctx, scope, jobID, expectedOwner)` derives comparison and payload from the SAME owner record/token. On CAS conflict reread and revalidate exact node/session/epoch; a successor tuple must be routed and gated independently. Do not call existing unrestricted BlockResource followed by FenceResource. Existing updateResourceFence retry loop cannot blindly carry permission across tuple changes.

Serialize local claim/release/retire transitions with owner per-scope transition primitive based on lockClaim. Audit lock order: mark retirement before waiting, never hold a transition lock while waiting for active work that can itself need ClaimWithReset. After drain acquire transition lock, reread tuple, then CAS; release may win before this point, in which case reroute. Claims must consult local retiring gate before granting local admission, but can acquire cleanup-only authority. Renew/touchOwnerSegment must preserve retirement fields and must not republish a stale record; ordinary CAS already prevents token races, yet successful retry must reread. ReleaseForPurge retains retirement lineage; ordinary release must not erase a prepared generation or permit reopening.

Do not replace background publication fence checks. Stop/quiesce capture only after foreground requests complete their durability waits. Existing Drop ignores errors during Forget; introduce an explicit verified capture-stop/drain result before claiming retirement barrier success where needed, rather than assuming Drop succeeded. Publication/compaction/queued upload checks continue to reject retired epochs, including delayed work from predecessors.

The RPC ACK requires durable retirement CAS plus still-valid local/lease proof. An ambiguous CAS/response leaves admission closed; retry rereads exact job/epoch and completes idempotently. After publication cleanupOwnedResource performs validated Forget, wake/timer cleanup, PurgeResource and ReleaseForPurge, then control completion. A stale cleanup after AllowResource must fail without closing a newer generation permanently: validate job and generation before installing the gate, and recheck on activation.

## Stage 4: dead owner and unowned cleanup

Add `owner.ClaimForResourceCleanup(ctx, scope, jobIdentity, reset)` rather than weakening Claim. Freshly read own.json and node lease (`liveFresh`, not cached routing); refuse an unreachable owner while it remains live. For expired owner, preserve BeforeTakeover recovery, monotonic nextEpoch, local reset-before-publish, and conditional CAS. Carry retirement identity/floor and publish retired=true in the same acquisition CAS; administrative ownership never opens normal admission. For an unretired dead/unowned scope, validate durable control job, install local gate first, and create/CAS a retired cleanup-only owner directly. This avoids an intermediate ordinary-owner admission window. For already retired scope accept only matching job; ordinary Claim continues ErrRetired. Reject newer incarnation or cleared same-job marker. Rerun recovery/lease checks after conflicting CAS instead of assuming the earlier dead-owner observation applies to a successor.

No control-row check is needed on EVERY ordinary request. New ordinary activations read current own.json/fence, bind local generation to tuple, and recheck after gate. A successor may activate while deletion is pending but before successful retirement publication; the coordinator must gate that successor before it can ACK deletion. If the intended contract instead prohibits any serving immediately after the registry commit (including pending failure), then a per-activation durable pending-job check is additionally required. Current code's asynchronous gap before BlockResource does not establish that stronger promise. Document the logical linearization point explicitly.

Switch both prepareResourceAccessSnapshot and the authoritative callbacks in beginPreparedResourceRequest/BeginResourceRequest to a common local-generation-proof provider. Fast proof binds generation + exact owner tuple + continuously healthy local lease generation + local lifecycle revision. Check before admission, under admission lock, and before read output; missing/invalid proof takes fresh ResourceSnapshot and normal ownership activation. Do not grant this proof to forwarded/nonowner nodes or across lease gaps, restart, release, local ownership invalidation, recreation, or capacity eviction. No TTL extension, background ordinary KV entries or pinned-auth changes. Keep fresh checks for all unproven paths.

## Scope and remaining blockers

Estimated 12-20 production files plus 8-12 test files, roughly 1-2k implementation LOC and comparable race/integration coverage; sizing is a review estimate, not a schedule or completed patch. Minimal safe staging: contracts/control durability -> lifecycle barrier -> exact-owner retirement + cleanup-only claim -> all caller integration -> fast local proof enabled last -> failure/idle acceptance. Keeping the one-second fence until the final stage allows incremental implementation, but does not make mixed binaries safe once the new fast path is enabled.

Unresolved proof gates before coding fast path: (1) complete timer/Store.Cell/background admission inventory, including direct open callbacks; (2) dead-owner recovery hook behavior on already retired epochs (must recover safely or demonstrate purge-only recovery semantics without changing RPO0); (3) exact lock order and capture-stop API error propagation; (4) durable control-owner validation transport without reentrant control capture deadlock; (5) bounded lifecycle reclamation tied to authority loss. These are concrete implementation tasks, not reasons to extend TTL.

No mixed-version claim: old binaries can directly BlockResource remotely. Enable only with a coordinated all-node upgrade/restart and drained old owners; process-local opt-in is unsafe in a fleet containing old writers. No new remote metadata is needed if deployment enforces that boundary. If coordinated upgrade cannot be guaranteed, keep the old one-second fence fast path disabled; adding a version capability to existing authority would be a separate contract decision.

## Capture quiescence prerequisite (2026-11-10)

Before invoking capture Drop for retirement, the coordinator closes admission and drains admitted/opening work, including foreground durability waits. Drop never opens Store.Cell: eviction can hold the store open lock. A timeout is not stopped proof. All cancellation paths (Drop, epoch change, owner watcher, Stop, initialization failure) retain the exact capture state until initialization and the capture loop/background baseline finish; Ensure cannot replace that state before completion. Waiting for initialization or shutdown respects the caller context. Initialization is cancelled by either its request or capture cancellation. Completed stopped states are removed automatically, so retention is bounded by unfinished captures rather than historical scopes. Resume hints are published only by a completed explicitly dropped state that still owns its map slot; ownership loss, epoch replacement, Stop, or ForgetHint suppress them. This is a local quiescence prerequisite, not retirement publication, cleanup-lease authority, or final retirement acceptance.

### Preserve files when capture quiescence fails

Store invalidation, explicit Forget and idle eviction must propagate/retain capture Drop failure rather than closing SQLite or deleting files. Keep resident bookkeeping until successful stop, release only the temporary eviction gate on failure, and allow retry against the same handle. A cancellation must not be interpreted as stopped proof. After a successful potentially blocking stop, destructive Forget verification must be checked again before removing the cache. Residency callbacks and eviction counters must not report a failed stop as success.

Failed-initializer publication review: a failed capture initializer must mark its exact state stopping while holding Manager.mu before closing ready. A cancelled capture goroutine may not have published Err/Done yet, so those signals cannot independently prevent a concurrent warm Ensure from accepting the failed initializer. This ordering is now regression-tested; full cellcapture race passed 2.176s. Cellstore removal paths preserve the resident DB/LRU/files when Drop returns an error or deadline, then revalidate destructive authorization after successful Drop before removal; full cellstore race passed 4.785s. Independent source review found no additional removal blocker. Production retirement integration remains pending.

### Cleanup acquisition integration

A cleanup-only acquired epoch is born retired and never admits ordinary data work. Its retirement floor must cover the new administrative epoch itself, not only its predecessor, so retries against the returned local tuple satisfy the same complete-retirement proof as live-owner preparation. This creates no additional object and never advances past a possible ordinary write: the acquisition publishes Retired atomically. A failed or lost acquisition acknowledgment leaves admission closed; subsequent retries must reread authority and reconcile only the same cleanup job/source identity under fresh validation.

### Guarded local retirement lifecycle prerequisite

Local gate rebind/reclaim uses exact expected identity and a scope exclusion reservation while fresh proof callbacks run outside Store.mu. Rebind preserves job/source and requires a drained scope without a resident handle; the callback must prove the administrative owner transition and stopped capture under caller-owned owner-transition serialization. Reclaim additionally requires all local DB/WAL/SHM/paged-marker files absent, and caller proof that capture stopped and all local ownership/read authority was discarded, with fresh authoritative loss/retirement or a distinct recreated generation. Proof callbacks must not reenter same-scope Store open/removal/lifecycle methods. Failure, missing proof or cancellation preserves admission closure; ordinary Forget never clears the gate. These primitives do not grant fresh ordinary owner activation by themselves. A point lookup exposes retained identity for exact retries after administrative claim ACK loss; no scan or remote metadata is introduced.

### Former-owner gate reclamation

Every cell-agent must reclaim historical local gates, including nodes that are not the control owner. A bounded local gate sweep runs before the control-owner-only cleanup pass; ordinary request preparation may trigger the same operation for its scope. Reclamation never times out a live gate: it first drains the exact gate, stops capture, then serializes local owner transitions and fresh-reads authority. It proceeds only when authority is absent or belongs to another node/session, discards local owner/read evidence, removes local cache files, refreshes resource-generation evidence, and clears only that exact gate. Same-process ownership at any epoch rejects reclamation, even when its lease looks expired. Bucket read failure or changed identity retains the gate; only local cache/gate state is removed, never remote data. Subsequent access must obtain fresh authority before serving. Successful cleanup's released-owner path remains separate. The sweep's pagination is over local gates, not bucket List, and must not starve gates beyond a persistently live entry.

### Cleanup lease checks inside bounded work

Administrative payload purge must require a caller validation callback and invoke it after listing and before each delete, then before reporting completion. The callback must not reenter the replica resource lock. Outer postchecks remain necessary; a point-in-time lease check cannot revoke an already in-flight provider operation.
