## 本轮修复链路

- Queue 配置：真实 HTTP 部署 101 并发被拒绝，100 被接受。
- D1：真实 workerd binding 查询读取 20,000 行并检查末行，五次公共 HTTP 总耗时 **73.962 / 88.769 / 67.210 / 61.238 / 75.313 ms**。外部客户端收到的是结果摘要，不是 20k 行全文。
- Queue 单节点：正常消费后 R2 metadata 正确；失败消费重试耗尽进入 DLQ，深度 1。
- Queue 双节点：先消费 5 条；失败消息进入 DLQ；SIGKILL 节点 1 和它的 runtime，等租约后向节点 2 发送 3 条，累计消费 8 条。
- 上述三个测试 namespace 均通过 DELETE app 清理，HTTP 200。测试 node/诊断权威对象可能按现有协议保留，未进行整桶删除。
- [COS 原语验收](hk-review-2026-10-25/provider.log)：实际云端 authority 条件删除与 raw S3 If-Match 条件删除均拒绝 stale ETag、接受当前 ETag，`go test -count=1 -v ./internal/bucket -run '^TestCOSConditionalDelete$'` 通过。

Queue 测试日志出现预期 DLQ 告警；单节点曾出现一次 `stale local cell is busy; retry ownership acquisition`，随后自动恢复并完成消费。未把它计为持久失败。

## 测试工具修正与初次失败

旧 cold harness 把 `/healthz` 当成服务完全就绪，真实 COS 初始化时 admin 端口尚未监听便执行 create app。现等待 `/readyz` 和 admin socket。

共享控制 cell 切换 owner 时另观察到建应用返回 `503 local_invalidation_failed`，未执行业务写；脚本现仅对此明确的写前拒绝做最多 30 次、有间隔的重试，不重放未知结果。该可用性现象保留记录。

旧 harness 的稳态 epoch 断言使用全节点 `epoch_changes_total`，共享测试桶中其它历史 scope 被后台恢复也会增加计数。现点查本次目标 cell 的 owner epoch 前后值；仍保留全节点计数用于观察，不将全局 List 增长直接认定为请求热路径 List。

中间一轮观察到重启首写 7,965ms，接管 TTFS 17,918ms，已确认键无丢失。该轮随后因运行期间修改脚本导致 shell 读取错位而中断，不能作为完整验收；已固定脚本并完整重跑。性能失败不因测试工具问题而隐去，也不放宽门槛。
