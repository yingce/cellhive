## 根因与修改

1. control 首次迁移的 migrated 检查与 DDL 不在同一临界区，40 个并发请求可执行重复 ALTER。改为串行初始化；新增 TestConcurrentColdSchema，修复前重复列失败，修复后通过。
2. 冷 cell 失效与 claim 分离，首请求进入 BeginRequest 后其他请求仍看到 unowned，误将忙碌 cell 当作旧副本。改为入请求门前用 ClaimWithReset 同 scope 串行门完成准备，保留 busy 旧副本拒绝接管。新增确定性复现；后台 claims 共用 owner 门，不自动重放业务请求。
3. Wrangler 重复发布的 JOBS binding 使用 inherit；metadata decoder 拒绝该类型并返回 invalid_multipart。新增继承 active 版本 binding/普通变量的处理；无 active/缺失名称拒绝，仍验证资源和 namespace，暂存不改变 active。
4. 冷启动 binding 鉴权遇到控制 owner 不存在或旧 session 直接失败，等待后台约 2 秒接管。现在主动走正常 claimForRead 恢复，再路由一次；本地读仍要求 owner/session/liveness 有效。
5. DO gate_500 实测是 WAL 读取与 workerd 写入交错产生瞬时 checksum mismatch。仅捕获观察最多重读 5 次（1/2/4/8ms 间隔）；持续损坏仍报错。跨失败保留 checkpoint 标志，避免重读/下一次 gate 漏掉全量快照。真实损坏 WAL 测试证明拒绝提交，修复字节后继续捕获；不重放非幂等 DO 调用。
6. wrk 即使 HTTP 500 也退出 0，DO 压测脚本新增 HTTP/socket 错误判失败。CF reconnect 的原始 WebSocket 探针无重连实现，B 重启后探针已断开却仍检查 Queue/Cron；重开该探针，官方 Wrangler 自身仍必须独立自动重连。多节点 CF Compose 遗漏 PEER_URL，两个节点默认127.0.0.1，导致 SIGKILL 接管时持久化身份校验拒绝；测试显式登记 agent-a/agent-b 的 DNS 地址，不放宽身份验证。
