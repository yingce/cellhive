# 换代后异步 Fold

状态：用户确认的设计，本地已实现，未提交、未部署。取代 2026-11-20 L0 batch/cascade/fold 设计中的空闲、交权前自动 Fold 触发约定。

## 概要

1. 同代只做 L0→L1；不按 L1 数量、时间、空闲或交权周期性刷新 L9/L2。
2. 新 owner 先 fencing、恢复并接续服务。新写进入当前 epoch；分页读者可以继续读取固定的旧链。
3. 后台发现 owned epoch，等待恢复链包含本代持久化对象，再固定本次输入切点 W，异步归并跨代依赖。
4. 完整链满足输入数、输入字节和逻辑数据库大小预算时，生成当前代 L9[1,W]；否则复用旧基线、分块归并 L2。1 GiB 是自动完整快照的逻辑大小/输入字节预算，不是上传硬限制。
5. 当前代已能独立恢复后停止自动维护；后续 L0/L1 不使 L9/L2 刷新。显式 admin snapshot 保持独立，不作为自动行为的保证。
6. 不改写、不删除输入。基线发布不等于读者已切换；物理回收继续走既有 GC 安全条件。

## 调度与失败

后台仅扫描 owner 的内存 owned 集合，未完成任务才读桶；热请求不 List，不等待 Fold。epoch 1 无跨代维护。新 epoch 尚无持久化接链对象时退避，不能在空 epoch 抢先发布基线。工作按 scope+epoch 去重，单个维护任务有超时；失败有退避，所有权丢失停止。成功状态内存缓存；进程重启或同代重新打开后，通过完整恢复链的 self-contained 判断幂等停止。

每次尝试固定一份恢复计划与 W，不用结束时可能增长的 durable watermark 报告本次覆盖。重试可基于最新合法恢复链重新规划，不承诺跨进程保存第一次失败尝试的 W。新上传尾部仍可恢复，L0→L1 游标独立。

## 基线与大 cell

沿实际完整恢复链找 L9 或 TXID 1 完整基线，不限上一代。输入可跨多个未完成维护的 epoch。完整 L9 一次原子发布，失败不删除源。完整合并超预算时，复用现有 Fold 的有界 L2、最新块先发布、基线最后发布顺序；已有大 L9 可流式复制，不受新建快照大小上限约束，但仍受临时盘与超时约束。没有 L9 则以 L2 承载完整基线。

中间代在发布部分 L2 后失主，后继沿实际恢复链续做；不能凭存在某个 L2 或 L9 就宣称完成。Fold 不阻塞交权，异步任务每次发布前检查 node/session/epoch 和 liveness。

## 场景与代价

- 繁忙 cell：接管后即有维护机会，不等 idle；完成后同代仅积累 L0/L1。
- 低频/纯读：后台 owned 扫描触发，不依赖新增 L1。
- 同代空闲重开：不刷新基线；本地数据有效可复用，分页旧读者继续受保护。
- 大 cell：搬基线加 L2，而不是强制全量快照。
- 长期不换代：L1 会增长，故障恢复可能变慢。本次不引入周期换代、同代 L2 重整或同代 L9 GC。
- 所有权已遗忘的休眠 cell 不占后台任务；再次激活发现 owned 时重试。当前代接链未持久化则暂不维护。

## 复用与验收

复用恢复选链、continuation、不可变 LTX、stream/spool、全局压缩资源槽、Verify、L0→L1 和 GC。新增换代后台调度及预算内全链 L9 策略，移除生产 idle/pre-release/rebalance/disk-shed 的自动 Fold。

验收：未接链不发布；预算内完整 L9；超预算 L2；连续多代缺基线；部分发布后续做；并发新写不推进本次切点；同代重试不刷新；失主停止；纯读 scope 可调度；超时退避；现有 compaction/replica/agent 回归。真实对象存储、故障进程和部署验收单独报告，不以单元测试替代。

兼容性：`CELLHIVE_L9_ON_EVICT` 配置字段暂保留解析，但不再控制自动快照；生产不注册 idle Fold 回调。旧的 FoldBaseline 原语保留供既有测试/显式调用，自动入口只使用 FoldEpoch。输入数量超过默认 256 时也会选择有界 L2 回退，即使逻辑库不足 1 GiB；不把大小当作唯一资源限制。

验证结果与限制见 [本地验证报告](../../reports/2026-11-22-epoch-fold.md)。

## 2026-11-23 纯读接管修订

GET/List 不调用 Capture.Ensure，不能假设接管后自然出现 continuation。后台 Fold 返回 waiting for current epoch 后，先校验当前 node/session/epoch 与 liveness，再通过 capture 的维护入口建立 continuation，然后重试 Fold。入口只 pin 已恢复的 resident cell，不打开已休眠/尚未恢复的 cell；要求预期 epoch 与 capture owner 相同，复用 Ensure 的单 scope 初始化协调、SeedContinuation/AdoptContinuation 及发布失败续做。不能接续持久链时返回错误，禁止维护入口退回整库 Snapshot。seed 发布前再次校验 owner，Fold 自身仍保留未接链禁止发布的保护。

capture 关闭时不建立 seed。维护在 capture 配置完成后启动，避免读取未初始化 manager。真实验收必须由 HTTP GET 完成 claim+hydrate，检查 GET 后只有前代对象，再启动维护；不得手工向本代写 LTX。原手工 seed 测试不构成纯读接管证据。

### 2026-11-23 空链休眠

仅当恢复规划成功且链确实为空时，后台 Fold 休眠；缺少基线但非空的链、读取失败和等待 continuation 均保持现有退避重试。每轮任务在扫描前保存 replica 的本代 L0 上传水位；休眠期间只比较内存水位，发生变化则重新规划，避免漏掉扫描/结果入队期间的上传。复用现有上传记账，直接 L0 发布同样有效，L1 覆盖 pending 对象不清除上传水位。不增加通知队列或桶轮询；epoch 改变或进程重启后重新发现一次。已自包含的 epoch 仍不因后续上传刷新。外部绕过本进程的同代写入不属于 owner 写路径；运维外部修改后可重启触发重新发现。

### 2026-11-23 同 owner 重开

owned 集合是后台扫描的本地提示，不是写权限证明。空闲驱逐移除该提示后，同 node/session 的请求重开快路径必须恢复登记；复用已验证的 live owner 信息，不为登记额外读写桶，不推进 epoch。忽略其他 node/session、退休和零 epoch 记录，也不以旧 epoch 覆盖已登记的新 epoch。请求有驻留门保护的路径与驱逐互斥；后台仍须重新验证 owner，不能凭登记直接删对象。控制面 claimForRead 同样恢复本地登记。
