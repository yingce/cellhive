## Current lifecycle contract

Native MAIN_DB handles share one per-path state. Every successful underlying open holds a reference; failed opens release it. Only the last clean underlying close acknowledges supervisor detach and removes native bitmap/registry state. Ambiguous or poisoned state remains fail-closed in a bounded registry. Admission saturation returns a recoverable open refusal before opening the underlying file, without fail-stopping a healthy child. Synchronous callback I/O retains the existing total5s budget (checkpoint preparation30s); registry locks are not held while waiting for per-path state or supervisor I/O.

Each native attach receives a fresh opaque48-hex session. Every non-open paging callback must carry the current session. Reopening a grown sparse file restores the same original cut, the decreasing truncate floor, ended checkpoint certificate/size, initial-file-validation state and supervisor poison/write/capture counters. Native xWrite marks touched pages; partial writes retain pre-hydration. Unaligned truncate fails before changing the floor. SIZE_HINT/CHUNK_SIZE bypasses are intercepted, mmap and xFetch are disabled, and callback exceptions cannot cross SQLite C boundaries. Production ambiguous paging failures retain exit74 fail-stop behavior.

Go separately bounds resident cut payloads, construction/resident page indexes, retained descriptors and local immutable-cut spill bytes. Defaults are128 resident payloads,4096 descriptors,32MiB logical descriptor budget,1GiB local state, and512MiB global logical page-index budget. Index allocation reserves before encoded-range and parsed-entry allocations. These are admission backstops and logical reachable-allocation accounting, not a measured whole-process RSS guarantee. Existing restore-plan allocations and opaque shared transports are not claimed to be precisely metered by the index quota.

An idle detached view spills its exact object keys/ETags, page index and hydrated bitmap into a checksummed local state file under a persistent sparse guard, using fsync/rename/directory sync. Eviction never hydrates the database or reads a newer remote head. Capture uses explicit BorrowCut/release so a loan cannot be evicted. Registry-wide locks are released before spill I/O. Startup accounts retained local guards/state; restart does not make unknown sparse cache ordinary authority. These files are local cache metadata, not remote markers or LTX format changes.

## Real retirement and capacity reuse

The loader admits `(host_hash, facet_id, storage identity, owner claim)` before `facets.get`. Numeric native paths are checked against a strictly parsed local `.facets` mapping and a current supervisor admission even when no guard/file exists. Explicit `PagingLifecycle` configuration enables this protocol; legacy gate-only runtimes retain their earlier gate behavior. Production paging runtime configuration enables it.

Retirement first closes admission, then aborts the facet/releases loader references and waits for actual native detach. Supervisor rejects pending opens, attached handles, cut borrowers, checkpoint preparation/copy and active writes; it serializes final WAL/pending capture with the file-state lock. A sparse retirement refuses the full-hydration snapshot fallback. Only after durability does it remove main/WAL/SHM and sync the parent directory, remove local cut/guard and sync again, then release descriptor, guard/state bytes, file-state cursor, claim cache and loader admission. Failed deletion stages retain the closed admission and retryable accounting. A queued capture path cannot resurrect a retired file-state entry because capture acquires its file lock through the live admission gate.

The next loader admission restores authoritative object scope before opening that same numeric path. Lost final retirement ACK is retryable via the absent current admission plus absent cache tuple; a successor's different token rejects stale retirement. Root Host metadata files are excluded from facet-cache deletion and retain existing handling.

Failed-new-restore cleanup is narrowly disposable: the entire cache tuple, guard and capture state must have been absent before that attempt. Such a failed attempt retains a bounded closed cleanup admission because its token was never delivered. A rejected existing descriptor, mismatching owner/scope or poisoned/uncaptured state never gets this discard authority and cannot skip the final durability proof.
